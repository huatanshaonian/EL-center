MIS-01 EL 屏 HDMI 显示程序（Tang Primer 20K + Dock）  使用说明
====================================================================
版本：v0.2（2026-10-19，加斜面"屏幕"开关输入 J14-12）
用途：Orange Pi 4 的 HDMI 画面（640×480）实时显示到 Sharp LJ64K052 EL 屏。
      同时包含测试程序的全部功能（8 种测试图案、上下电顺序、保护），可替代测试程序使用。
状态：电脑仿真全部通过、开源工具链编译通过；还没有在实物上运行过。

--------------------------------------------------------------------
1. 数据通路
--------------------------------------------------------------------
  Orange Pi ─HDMI─▶ Dock HDMI 口
    → EDID：FPGA 自报为 “MIS-01 EL”，只支持 640×480@60
    → TMDS 接收、解码（复用 tang-monitor 在同款 Dock 上实测成功的代码，MIT 许可）
    → 转黑白：亮度 = (77R + 150G + 29B)/256，与阈值比较；可选 4×4 Bayer 抖动、反色
    → 8 像素打包 → 跨时钟 FIFO → 双帧缓存（片上 BSRAM，38/46 块）
    → 只在屏的帧边界换帧（不撕裂，上下半屏总是同一帧）
    → 屏扫描时序（与测试程序相同：CP2 5.4 MHz、60/120 Hz）
  只收完整、尺寸正确（每行 640 像素、480 行）的帧；残缺帧整帧丢弃，屏继续显示上一帧。
  画面更新率：屏刷新 60 Hz 不变；新画面更新约 30–60 帧/秒（取决于输入与屏两边帧相位，缓慢变化）。

--------------------------------------------------------------------
2. 编译与烧录
--------------------------------------------------------------------
  编译（我这边已编好，一般不用你操作）：在 WSL 里
      bash /mnt/e/modeling/MIS-01/fpga/build.sh el_hdmi
  产物：fpga/el_hdmi/build/el_hdmi_top.fs
  Orange Pi 拒绝 640×480 时，改用 27 MHz 版 EDID 重新编译：
      EDID=edid/edid_640x480_27m.hex bash /mnt/e/modeling/MIS-01/fpga/build.sh el_hdmi

  烧录：
    1. Dock 的 1 号拨码开关拨下（否则核心板不工作，JTAG 能扫到但写不进）。
    2. USB-C 线接 Dock 的“USB-JTAG&UART”口。
    3. 高云 Programmer → 认出 GW2A-18C → Operation 选 SRAM Program → File 选 el_hdmi_top.fs → 运行。
       （.fs 由开源工具链 apicula 生成，格式与高云的相同。若 Programmer 不认，告诉我，改用 openFPGALoader。）
    4. 烧完立即运行；断电后 FPGA 空白、所有脚弱上拉、OE_N 为高，屏信号输出关闭。

  接线：不要插 40P RGB 屏排线（J7）、麦克风阵列排线（J15）、DVP 摄像头，它们与本程序用的脚共用。

--------------------------------------------------------------------
3. 按键
--------------------------------------------------------------------
  RUN（T10）：开机 / 关机 / 清除故障（同测试程序）
  SRC（T3） ：切换信号源 0→1→…→9→0
  HPD（T2） ：拉一下 HPD，让 Orange Pi 重新读 EDID、重新输出
  （T10 在 Sipeed 例程里是“复位键”；三颗键的板上位置请上电后逐个按一下确认）

  信号源：
    0     HDMI 视频（上电默认）：没有合格画面时显示全黑
    1..8  测试图案 0..7（同测试程序：全黑、稀疏点、边框、棋盘、竖线、横线、竖条反相、全亮）
    9     帧缓存自检：FPGA 自己往缓存里写一幅会动的画面（边框 + 移动的竖线和横线 + 左上角 8 个方块显示帧号），
          不接 HDMI 也能检查帧缓存的地址、上下半屏和换帧；线条应平滑移动、不撕裂，横线跨过屏中缝时连续。

  屏幕开关（Dock J14-12，P6，EL-IF D1.2 起经 J_PF-2 接斜面钮子开关）：
    高 = 允许开屏（EL-IF 上 10k 上拉；J_PF 不插、或面包板阶段悬空时都是高）
    低 = 关屏：EL-IF 上 D4 直接把 EN_VD 拉低（硬件关 VD）；FPGA 同时撤掉 VD_ON_N，扫描照常继续。
    开关重新打开：去抖 20 ms 后再等 100 ms 才放开 VD_ON_N，避免 D4 一松 VD 在 FPGA 没准备时上电。
    上电时同样先等这 120 ms。只控制 VD，不影响 OE、扫描和信号源。

--------------------------------------------------------------------
4. 状态灯（6 个，低电平点亮）
--------------------------------------------------------------------
  LED0 OE 已使能          LED1 正在扫描          LED2 VD_ON_N=0（面包板阶段：可以手动开 VD）
  LED3 故障快闪 / PFAIL 慢闪
  LED4 HDMI 已锁定（时钟恢复 + 三条通道对齐）
  LED5 正在显示 HDMI 视频；每换一帧新画面翻转一次（有画面更新时闪烁）
  切换信号源后 1 秒内，LED0..LED3 显示信号源编号（二进制，LED0 = 最低位）。

--------------------------------------------------------------------
5. 串口命令（115200 8N1）
--------------------------------------------------------------------
  两个口共用同一套命令：
    Orange Pi：J14-10 = FPGA 发 → 接 Orange Pi RX；J14-11 = FPGA 收 → 接 Orange Pi TX（3.3V）
    电脑：Dock 的 USB 调试串口（插 USB-C 后出现两个串口，一般是第二个）
  一行一条，回车结束，不分大小写：
    R1 / R0      开机 / 关机（R1 也用于清除故障）
    S0..S9       信号源（见第 3 节）
    T0..T255     阈值，默认 128（抖动模式下是亮度偏移，128 = 不偏移）
    I1 / I0      反色
    D1 / D0      Bayer 抖动
    F60 / F120   屏刷新率
    O0..O255     无 HDMI 信号多少秒后自动关 VD（默认 60；0 = 不关）。信号恢复后自动重新开 VD
    P            同 HPD 键
    ?            状态，例如：
                 ST=3 SRC=0 HDMI=1 VID=1 SHOWN=1234 DROP=00AB H=280 V=1E0 T=80 I=0 D=0 F=060 O=3C -
                 ST 上下电状态（0 关机 1 OE 已开 2 扫描中 3 运行 4 关 VD 中 5 停扫描 6 关 OE 7 故障）
                 SHOWN/DROP 已换上/丢弃的帧数（十六进制），H/V 最近一帧的有效像素/行数（应为 280/1E0 = 640/480）
                 最后一个字符：- 正常，F 故障，P 发生过 PFAIL，X FIFO 溢出
  回应 OK / ERR。Orange Pi 上可以：stty -F /dev/ttyS? 115200 raw; echo "T100" > /dev/ttyS?

--------------------------------------------------------------------
6. 建议的第一次上板顺序（先不接屏）
--------------------------------------------------------------------
  1. 只接 USB-C，烧录。四盏灯（LED0..3）应全灭，LED4/5 灭。
  2. 电脑串口发 “?”，确认能收到状态行。
  3. Orange Pi 接 Dock 的 HDMI，开机：LED4 应亮；“?” 里 H=280、V=1E0、SHOWN 在增长。
     LED4 不亮：先确认 Orange Pi 能输出 640×480（设计笔记 U12），再试 HPD 键；还不行用 27 MHz 版 EDID。
  4. 用示波器在 Dock 的 J5/J6 上看 CP2/CP1/S（按 RUN 开机后才有）。
  5. 之后按面包板文档实验 3、4 接屏。实验 3 可以用信号源 1..8（测试图案），实验 4 再切到 0（HDMI）。

8. 验证情况
--------------------------------------------------------------------
  仿真（iverilog）：
    tb_fb_path   模拟 640×480 信号源 → 完整通路 → 屏端逐帧采集：19 帧逐像素正确、无撕裂、上下半屏同一帧；
                 故意做坏的一帧（某行 639 像素）没有显示；断信号变黑、恢复后继续显示；FIFO 无溢出
    tb_local     自检画面经帧缓存显示正确，生成快于显示时整帧丢弃
    tb_ctrl_cmd  16 条命令（含 8 条错误命令）经真实串口收发，回应与设置正确；状态行格式正确
    tb_pixel_mono 20 万组随机颜色/阈值/抖动位置，与参考模型一致
    tb_screen_switch 开关抖动不响应；关立即禁止 VD；开后延时放开；延时中再关立即禁止并重新计时
    另：测试程序的三组仿真（扫描时序按 6 拍 RAM 延迟取数、上下电顺序 6 项场景、顶层）
  编译（yosys + nextpnr-himbaechel + apicula，2026-10-18 版 oss-cad-suite）：
    BSRAM 38/46、LUT4 17%、rPLL 2/4；54 MHz 域最高 96 MHz、像素时钟域最高 109 MHz（需 25.2 MHz）（v0.2 重新编译）
  没有验证的：HDMI 接收在 Orange Pi 上能否锁定（tang-monitor 只用 Mac 测过）、SDPB 满深度（2K×8）在实物上读写、
             实物按键位置。第一次上板时请按第 6 节顺序，把串口 “?” 的输出发给我。
