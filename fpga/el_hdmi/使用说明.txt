MIS-01 EL 屏 HDMI 显示程序（Tang Primer 20K + Dock）  使用说明
====================================================================
版本：v0.2（2026-10-19，加斜面"屏幕"开关输入 J14-12）；2026-10-20 首次上板，见第 8 节
用途：Orange Pi 4 的 HDMI 画面（640×480）实时显示到 Sharp LJ64K052 EL 屏。
      同时包含测试程序的全部功能（8 种测试图案、上下电顺序、保护），可替代测试程序使用。
状态：已在实物上运行：烧录、按键、LED、串口命令、帧缓存自检正常；Pi 能读到 EDID。
      HDMI 视频还没收到：手上的 Dock 是 v3714，HDMI 口没有接收端接（见第 6 节），需外加端接后再测。

--------------------------------------------------------------------
1. 数据通路
--------------------------------------------------------------------
  Orange Pi ─HDMI─▶ Dock HDMI 口
    → EDID：FPGA 自报为 “MIS-01 EL”，只支持 640×480@60
    → TMDS 接收、解码（复用 tang-monitor 在同款 Dock 上实测成功的代码，MIT 许可）
    → 转黑白：亮度 = (77R + 150G + 29B)/256，与阈值比较；可选 4×4 Bayer 抖动、反色
    → 8 像素打包 → 跨时钟 FIFO → 双帧缓存（片上 BSRAM，38/46 块）
    → 只在屏的帧边界换帧（不撕裂，上下半屏总是同一帧）
    → 屏扫描时序（与测试程序相同：CP2 5.4 MHz、60/120 Hz）
  只收完整、尺寸正确（每行 640 像素、480 行）的帧；残缺帧整帧丢弃，屏继续显示上一帧。
  画面更新率：屏刷新 60 Hz 不变；新画面更新约 30–60 帧/秒（取决于输入与屏两边帧相位，缓慢变化）。

--------------------------------------------------------------------
2. 编译与烧录
--------------------------------------------------------------------
  编译（我这边已编好，一般不用你操作）：在 WSL 里
      bash /mnt/e/modeling/MIS-01/fpga/build.sh el_hdmi
  产物：fpga/el_hdmi/build/el_hdmi_top.fs
  Orange Pi 拒绝 640×480 时，改用 27 MHz 版 EDID 重新编译：
      EDID=edid/edid_640x480_27m.hex bash /mnt/e/modeling/MIS-01/fpga/build.sh el_hdmi

  Orange Pi 4 只接受 27 MHz 版 EDID（2026-10-20 实测：25.175 MHz 的 640×480 被内核拒绝，模式列表为空）。
  给 Orange Pi 用时请按上面第二条命令编译。

  烧录：
    1. Dock 的 1 号拨码开关：v3713 及更早必须拨下（它接 RECONFIG_N）；v3714 上它只是普通 IO，位置无所谓。
    2. USB-C 线接 Dock 的“USB-JTAG&UART”口。电脑上出现一个 USB 串口（本机是 COM4）就是调试串口。
    3. 高云 Programmer → 认出 GW2A-18C → Operation 选 SRAM Program → File 选 el_hdmi_top.fs → 运行。
       命令行：programmer_cli.exe --device GW2A-18C --run 2 --fsFile <el_hdmi_top.fs 的完整路径>
       成功时显示 Status Code 0x00006020、Finished。
       注意：apicula 生成的 .fs 原本没有开头的 // 注释头，Programmer 会进度走完后报 "Error found!"、
       芯片加载不完成（状态 0x00000020）。build.sh 已自动调用 scripts/fs_header.py 补上注释头，不用手动处理。
    4. 烧完立即运行；断电后 FPGA 空白、所有脚弱上拉、OE_N 为高，屏信号输出关闭。
       加载失败或按了 S4（v3714 上是 RECONFIG_N）时，FPGA 会改从 Flash 加载出厂程序（丝印 3、4 号灯闪）。

  接线：不要插 40P RGB 屏排线（J7）、麦克风阵列排线（J15）、DVP 摄像头，它们与本程序用的脚共用。

3. 按键
--------------------------------------------------------------------
  RUN（T10，板上丝印 S0）：开机 / 关机 / 清除故障（同测试程序）
  SRC（T3， 板上丝印 S1）：切换信号源 0→1→…→9→0
  HPD（T2， 板上丝印 S2）：拉一下 HPD，让 Orange Pi 重新读 EDID、重新输出
  S3 不用。S4 不要按：v3714 上 S4 接 FPGA 的 RECONFIG_N，按下会丢掉 SRAM 里的程序、改加载 Flash。
  （2026-10-20 实测确认）

  信号源：
    0     HDMI 视频（上电默认）：没有合格画面时显示全黑
    1..8  测试图案 0..7（同测试程序：全黑、稀疏点、边框、棋盘、竖线、横线、竖条反相、全亮）
    9     帧缓存自检：FPGA 自己往缓存里写一幅会动的画面（边框 + 移动的竖线和横线 + 左上角 8 个方块显示帧号），
          不接 HDMI 也能检查帧缓存的地址、上下半屏和换帧；线条应平滑移动、不撕裂，横线跨过屏中缝时连续。

  屏幕开关（Dock J14-12，P6，EL-IF D1.2 起经 J_PF-2 接斜面钮子开关）：
    高 = 允许开屏（EL-IF 上 10k 上拉；J_PF 不插、或面包板阶段悬空时都是高）
    低 = 关屏：EL-IF 上 D4 直接把 EN_VD 拉低（硬件关 VD）；FPGA 同时撤掉 VD_ON_N，扫描照常继续。
    开关重新打开：去抖 20 ms 后再等 100 ms 才放开 VD_ON_N，避免 D4 一松 VD 在 FPGA 没准备时上电。
    上电时同样先等这 120 ms。只控制 VD，不影响 OE、扫描和信号源。

--------------------------------------------------------------------
4. 状态灯（6 个，低电平点亮）
--------------------------------------------------------------------
  板上丝印编号与这里相反：LED0..LED5 = 丝印 5..0（LED0..3 已实测；LED4/5 = 丝印 1/0 按原理图）。
  LED0 OE 已使能          LED1 正在扫描          LED2 VD_ON_N=0（面包板阶段：可以手动开 VD）
  LED3 故障快闪 / PFAIL 慢闪
  LED4 HDMI 已锁定（时钟恢复 + 三条通道对齐）
  LED5 正在显示 HDMI 视频；每换一帧新画面翻转一次（有画面更新时闪烁）
  切换信号源后 1 秒内，LED0..LED3 显示信号源编号（二进制，LED0 = 最低位）。
  信号源 0 且无 HDMI 超过 O 秒（默认 60 s，上电即算超时）时 VD 被禁止：按 RUN 后只有 LED0、LED1 亮，
  LED2 不亮，这是正常的保护。切到信号源 1..8（测试图案）或发命令 O0 后 LED2 才会亮。

--------------------------------------------------------------------
5. 串口命令（115200 8N1）
--------------------------------------------------------------------
  两个口共用同一套命令：
    Orange Pi：J14-10 = FPGA 发 → 接 Orange Pi RX；J14-11 = FPGA 收 → 接 Orange Pi TX
               用 Orange Pi 4 的 UART4：40 针 19 脚 = TX、21 脚 = RX、GND 任一地脚；
               Armbian 里先开 overlay：/boot/armbianEnv.txt 加 overlays=rk3399-uart4（会关掉 SPI1），重启后是 /dev/ttyS4。
               注意 Orange Pi 4 排针电平是 3.0 V（不是 3.3 V）：FPGA 发出的 3.3 V 要经 EL-IF 上的 RTX 串阻再进 Orange Pi。
    电脑：Dock 的 USB 调试串口（插 USB-C 后出现两个串口，一般是第二个）
  一行一条，回车结束，不分大小写：
    R1 / R0      开机 / 关机（R1 也用于清除故障）
    S0..S9       信号源（见第 3 节）
    T0..T255     阈值，默认 128（抖动模式下是亮度偏移，128 = 不偏移）
    I1 / I0      反色
    D1 / D0      Bayer 抖动
    F60 / F120   屏刷新率
    O0..O255     无 HDMI 信号多少秒后自动关 VD（默认 60；0 = 不关）。信号恢复后自动重新开 VD
    P            同 HPD 键
    ?            状态，例如：
                 ST=3 SRC=0 HDMI=1 VID=1 SHOWN=1234 DROP=00AB H=280 V=1E0 T=80 I=0 D=0 F=060 O=3C -
                 ST 上下电状态（0 关机 1 OE 已开 2 扫描中 3 运行 4 关 VD 中 5 停扫描 6 关 OE 7 故障）
                 SHOWN/DROP 已换上/丢弃的帧数（十六进制），H/V 最近一帧的有效像素/行数（应为 280/1E0 = 640/480）
                 最后一个字符：- 正常，F 故障，P 发生过 PFAIL，X FIFO 溢出
  回应 OK / ERR。Orange Pi 上可以：stty -F /dev/ttyS4 115200 raw; echo "T100" > /dev/ttyS4

6. 建议的第一次上板顺序（先不接屏）
--------------------------------------------------------------------
  1. 只接 USB-C，烧录。四盏灯（LED0..3）应全灭，LED4/5 灭。
  2. 电脑串口发 “?”，确认能收到状态行。
  3. Orange Pi 接 Dock 的 HDMI，开机：LED4 应亮；“?” 里 H=280、V=1E0、SHOWN 在增长。
     LED4 不亮时按下面的顺序查。

  接 Orange Pi 的注意事项（2026-10-20 实测）：
    - 先给 Pi 接它自己的电源开机，再插 HDMI；关 Pi 前先拔 HDMI。
      Dock 的 HDMI 5V（18 脚）由 +5V 经 D5 往外送，Pi 没电时会被它反向供电（Pi 红灯亮）。
      Pi 开着时它自己的 5V 更高，D5 截止，不会倒灌。
    - 用 27 MHz 版 EDID（第 2 节）。25.175 MHz 版 Pi 读得到但模式列表为空、不输出。
    - 本机 Pi 的 /boot/armbianEnv.txt 有 extraargs=drm.edid_firmware=HDMI-A-1:edid/1920x1280.bin
      （为另一块 1920×1280 屏强制 EDID），会无视 FPGA 的 EDID。测试时只在运行时改，不动文件：
          echo "HDMI-A-9:none" | sudo tee /sys/module/drm/parameters/edid_firmware
      然后按 HPD 键（或串口发 P）。重启 Pi 自动恢复。
      查看：cat /sys/class/drm/card0-HDMI-A-1/modes 应只有 640x480；strings 该目录下 edid 应含 "MIS-01 EL"。
    - Dock v3714 的 HDMI 口不能直接当接收端：P004 页 R15–R22 由 3713 的 49.9Ω 上拉到 HDMI_3V3（接收端接）
      改成了 499Ω 下拉到 GND（Sipeed 修改说明 "DVI optimize"）。没有端接，Pi 的 PHY_STAT0 RX_SENSE 全为 0，
      TMDS 线上没有摆幅，FPGA 时钟脚完全收不到信号（tang-monitor 的 m5 调试程序报 L00：PLL 未锁、重捕获次数 0）。
      解决：在 Pi 和 Dock 之间加直通转接，8 根 TMDS 线（1/3、4/6、7/9、10/12 脚）各 51Ω 上拉到 3.3V，
      18 脚 5V 断开。tang-monitor 是在 3709 版 Dock 上验证的，它说的“零改动”只适用于 3713 及更早。
      判断板子版本：丝印 vXXXX 在核心板插槽中间，需拔下核心板才能看到。
  4. 用示波器在 Dock 的 J5/J6 上看 CP2/CP1/S（按 RUN 开机后才有）。
  5. 之后按面包板文档实验 3、4 接屏。实验 3 可以用信号源 1..8（测试图案），实验 4 再切到 0（HDMI）。

8. 验证情况
--------------------------------------------------------------------
  仿真（iverilog）：
    tb_fb_path   模拟 640×480 信号源 → 完整通路 → 屏端逐帧采集：19 帧逐像素正确、无撕裂、上下半屏同一帧；
                 故意做坏的一帧（某行 639 像素）没有显示；断信号变黑、恢复后继续显示；FIFO 无溢出
    tb_local     自检画面经帧缓存显示正确，生成快于显示时整帧丢弃
    tb_ctrl_cmd  16 条命令（含 8 条错误命令）经真实串口收发，回应与设置正确；状态行格式正确
    tb_pixel_mono 20 万组随机颜色/阈值/抖动位置，与参考模型一致
    tb_screen_switch 开关抖动不响应；关立即禁止 VD；开后延时放开；延时中再关立即禁止并重新计时
    另：测试程序的三组仿真（扫描时序按 6 拍 RAM 延迟取数、上下电顺序 6 项场景、顶层）
  编译（yosys + nextpnr-himbaechel + apicula，2026-10-18 版 oss-cad-suite）：
    BSRAM 38/46、LUT4 17%、rPLL 2/4；54 MHz 域最高 96 MHz、像素时钟域最高 109 MHz（需 25.2 MHz）（v0.2 重新编译）
  实物（2026-10-20，Dock v3714，只接 USB-C 与 HDMI，不接屏和 EL 接口板）：
    - 烧录：补 // 注释头后 SRAM Program 成功（状态 0x6020）；不补则报 "Error found!"（见第 2 节）。
    - 上电：LED 全灭；串口 COM4 115200 “?” 回 ST=0 SRC=0 HDMI=0 VID=0 SHOWN=0000 DROP=0000 H=000 V=000
      T=80 I=0 D=0 F=060 O=3C -，与预期一致。
    - 按键：S0=RUN、S1=SRC（信号源 1..9 依次以二进制显示在丝印 5/4/3/2，约 1 秒）、S2=HPD。
    - LED 极性：低电平点亮，与假设一致；LED0..3 = 丝印 5..2。
    - 开关机：信号源 1 下 R1 → ST=3，丝印 3/4/5 全亮；R0 → 丝印 3 先灭，约 1 s 后 4、5 灭。
      信号源 0 无 HDMI 时开机丝印 3（VD）不亮，是无信号保护（第 4 节）。
    - 帧缓存自检：S9 后 SHOWN 持续增长、DROP=0，SDPB 读写正常。命令 XYZ 回 ERR。
    - HDMI：Pi（Armbian 6.18.56）读到 “MIS-01 EL”；27 MHz 版 EDID 下 Pi 以 640×480@27 MHz 输出
      （VPLL/dclk_vop0 = 27 MHz）；但 Dock v3714 无接收端接，FPGA 未锁定（HDMI=0）。待加端接转接后再测。
  没有验证的：HDMI 接收锁定与解码、实物屏、示波器波形（J5/J6）、LED4/5 位置。
