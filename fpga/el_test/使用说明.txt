MIS-01 EL 屏测试时序程序（Tang Primer 20K + Dock）  使用说明
====================================================================
版本：v0.1（2026-10-19）
用途：面包板实验 3（动态波形）、实验 4（首次点屏）。输出 LJ64K052 完整扫描时序和 8 种测试图案，
      并按规定顺序控制 OE_N、VD_ON_N。
状态：已通过电脑仿真（见第 6 节）；还没有在实物上编译、烧录或测量过。

--------------------------------------------------------------------
1. 时序参数（设计笔记 §8.3）
--------------------------------------------------------------------
  内部时钟 54 MHz（27 MHz 晶振经 PLL ×2）
  CP2      5.4 MHz，高/低各 92.6 ns；每行 160 个
  CP1      高 148 ns；周期 69.44 µs
  帧       240 行、无垂直空白，60.0 Hz
  CP1↓ → 首个 CP2↑ 148 ns，→ 首个 CP2↓ 241 ns
  数据     在 CP2↑ 时更换；对 CP2↓ 的建立/保持各 92.6 ns
  S        在锁存第 0 行的那次 CP1↓ 前后为高：建立 444 ns、保持 74 ns

3. 编译与烧录
--------------------------------------------------------------------
  准备
    - Gowin EDA 教育版（V1.9.9 或更新），Gowin Programmer（已下载在 D:\gowin）。
    - Dock 板上的 1 号拨码开关拨下，否则核心板不工作，且 LED0、LED1 常亮（Sipeed Wiki）。
    - USB-C 线接 Dock 的“USB-JTAG&UART”口（板载 BL702 下载器，不用另买）。
    - 不要插 40P RGB 屏排线（J7）和麦克风阵列排线（J15），它们和 J5/J6/J14 共用 FPGA 引脚。

  编译
    1. Gowin EDA → File → Open Project → 选 el_test.gprj。
    2. 确认器件为 GW2A-LV18PG256C8/I7（Device 栏 GW2A-18C）。
    3. 点 “Run All”（或依次 Synthesize → Place & Route）。
    4. 生成的烧录文件：impl/pnr/el_test.fs
    5. 如果报某个引脚是“复用脚/已被占用”（dual-purpose pin），把报错原文发给我。
       通常是在 Project → Configuration → Place & Route → Dual-Purpose Pin 里勾选对应项，
       但不要勾 JTAG：勾了以后下载器会认不出 FPGA。

  烧录（测试阶段用 SRAM，断电即丢，最安全）
    1. 打开 Gowin Programmer → Scan Device（或 USB Cable Setting 里选 USB Debugger A）。
    2. 认出 GW2A-18C 后，Operation 选 “SRAM Program”，File 选 impl/pnr/el_test.fs。
    3. Program/Configure。完成后程序立即运行，4 个状态灯应全灭。
    4. 断电后 FPGA 回到空白状态：所有脚弱上拉，OE_N 为高，屏信号输出保持关闭。
    确认程序没问题后，才考虑烧进 Flash（Operation 选 exFlash 相关项）。

4. 按键与状态灯
--------------------------------------------------------------------
  按键（引脚 T10、T3；在 Sipeed 资料里 T10 是例程用的“复位键”，具体是板上哪颗请上电后按一下确认）
    RUN（T10）：OFF 时按 = 开机；运行中按 = 关机；故障停机后按 = 清除故障
    PAT（T3） ：切换下一个测试图案，0→7 循环；上电默认 0（全黑）

  状态灯（LED0..LED3 = 引脚 L16、L14、N14、N16；LED4/LED5 不用）
    LED0 亮 = OE 已使能（OE_N=0）
    LED1 亮 = 正在扫描
    LED2 亮 = VD_ON_N=0。面包板阶段 VD 由人工开关，这盏灯亮表示“现在可以开 VD”
    LED3 快闪（4 Hz）= eFuse 故障；慢闪（1 Hz）= 发生过 24V 掉电（PFAIL）
    按 PAT 后 1 秒内，LED0..LED2 改为显示图案号（二进制：LED0 = 最低位）
  灯的亮灭和上面说的正好相反时：说明 Dock 的灯是高电平点亮。把 el_test_top.v 里
  LED_ACTIVE_LOW 改成 0 再编译，并告诉我。

  测试图案（按点亮面积从小到大）
    0 全黑
    1 稀疏点（每 16×16 一个点）
    2 边框 + 左上角 32×32 实心方块 + 上下半屏交界（第 240/241 行）横线：查方向、镜像、上下半屏
    3 8×8 棋盘格
    4 每 8 列一条竖线
    5 每 8 行一条横线
    6 4 像素宽竖条、逐行反相：每根数据线每个 CP2 都翻转，测波形最严酷
    7 全亮（电流最大，VD 限流 2.0A 时才用）

5. 操作顺序（与面包板文档实验 3、4 对应）
--------------------------------------------------------------------
  开机：按 RUN →
    ① OE 使能（LED0 亮），信号全低，等 1 ms
    ② 开始扫描（LED1 亮）
    ③ 稳定扫描 2 整帧（约 33 ms）后，VD_ON_N=0（LED2 亮）
    实验 3：此时 VD 保持关闭，用示波器在 CN5 端测波形，可按 PAT 换图案。
    实验 4：LED2 亮后，再手动打开可调电源的 VD 输出。

  关机：先手动关 VD 输出，等 CN5 端 VD 降到 1V 以下，再按 RUN →
    ① VD_ON_N=1（LED2 灭），扫描继续
    ② 再等 1 秒（T_VD_WAIT，暂定值，PCB 阶段按实测改）
    ③ 扫完当前整帧后停止扫描（LED1 灭）
    ④ OE 禁用（LED0 灭）
    最后再拔 USB 5V（关 VL）。

  保护（面包板阶段这些线悬空，FPGA 内部上拉读作“正常”，不会触发；上 PCB 后才起作用）
    VL_OK 变低     ：立即关 VD、停扫描、禁用 OE
    PFAIL_N 变低   ：立即关 VD，VL 还在就继续扫描，按关机流程走完；LED3 慢闪
    VD/VL_FLT_N 变低：立即关 VD，走完关机流程后停在故障状态，LED3 快闪；故障线恢复后按 RUN 清除

6. 仿真验证（已通过）
--------------------------------------------------------------------
  运行：在 WSL 里执行  bash /mnt/e/modeling/MIS-01/fpga/el_test/sim/run_sim.sh
  tb_scan_timing  逐条检查 CP2/CP1/S 的宽度、周期、建立/保持、tS12/tS13；
                  每行 160 组、每帧 240 行、帧周期 60 Hz；全部像素与独立参考模型逐个比对；
                  停止时扫完整帧、中止时 2 个时钟内全部输出变低。共 4 帧、825 行。
  tb_power_seq    正常开关机顺序、VD 未降时一直扫描、PFAIL / 故障 / VL 掉电三种保护、
                  不满足条件时不能开机；全程检查“VD 开时必须在扫描且 OE 使能”。
  tb_top          顶层连线、复位状态、按键、LED 极性、开机到关机全过程。
  另外故意改坏两处（首个 CP2 提前、像素位序反了）重跑，测试都能报错，说明检查有效。

  仿真不能代替的事项
    - 高云工具的实际编译、引脚复用设置、时序报告（第一次编译后把报告给我看）
    - 实物 LED 极性、按键位置
    - CN5 端真实波形（经 245、串阻和线束后）——实验 3 必须用示波器测

7. 以后要改的参数（el_test_top.v 顶部）
--------------------------------------------------------------------
  VD_WAIT_CYCLES  关 VD 后等多久停扫描，默认 54000000（1 s）；按实测 VD 衰减时间 ×2 改
  SCAN_FRAMES     开 VD 前稳定扫描的整帧数，默认 2
  LED_ACTIVE_LOW  LED 极性
  120 Hz 测试：把 el_scan_timing 的 LINE_TICKS 从 3750 改成 1875（行周期 34.7 µs，仍满足 ≥ 31 µs）
